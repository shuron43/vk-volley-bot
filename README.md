# VK Volleyball Bot

Бот для группового чата VK, который автоматически собирает участников на волейбол: еженедельный анонс по расписанию, напоминание перед сбором, запись себя и друзей по имени, inline-клавиатура и админ-команды.

---

## Стек

- **Python** 3.12+
- **uv** — управление зависимостями и виртуальным окружением
- **vkbottle** 4.x — фреймворк для VK-ботов
- **anyio** — структурированная асинхронность
- **pydantic + pydantic-settings** — валидация конфигурации
- **ruff + basedpyright** — линтер и type checker в строгом режиме

## Быстрый старт

```bash
# 1. Клонирование и установка
git clone <repo-url> vk-volleyball-bot
cd vk-volleyball-bot
uv sync

# 2. Настройка окружения
cp .env.example .env
# Заполните .env: VK_TOKEN, CHAT_PEER_ID

# 3. Запуск
uv run python -m src.main
```

### Настройка сообщества VK

#### 1. Включи сообщения и возможности бота

1. Управление сообществом → **Сообщения** → включи **Сообщения сообщества**
2. Там же → **Настройки для бота** → включи **Возможности ботов**
3. Поставь галочку **Разрешать добавлять сообщество в беседы** — без неё бота нельзя пригласить в чат

#### 2. Включи Long Poll API

1. Управление сообществом → **Работа с API** → **Long Poll API**
2. Включи **Long Poll API** и выбери актуальную версию API (не ниже 5.80)
3. На вкладке **Типы событий** отметь:
   - ✅ **Входящее сообщение** (`message_new`) — текстовые команды боту
   - ✅ **Действие с сообщением** (`message_event`) — нажатия на inline-кнопки

> ⚠️ **Важно:** без события `message_event` inline-клавиатура не будет реагировать на нажатия.

#### 3. VK_TOKEN

1. Открой настройки своего сообщества VK → **Работа с API** → **Ключи доступа**
2. Нажми **Создать ключ**
3. Включи разрешения:
   - ✅ **Разрешить приложению управление сообществом**
   - ✅ **Разрешить приложению доступ к сообщениям сообщества**
4. Скопируй токен и вставь в `.env`

> ⚠️ **Важно:** Не коммить `.env` в git. Файл уже добавлен в `.gitignore`.

#### 4. Добавление бота в беседу

1. После включения «Разрешать добавлять сообщество в беседы» на странице сообщества появится кнопка **Пригласить в беседу** — выбери нужный чат. Либо из самого чата: шапка беседы → **Управление** → **Участники** → **Добавить** → выбери сообщество.
2. Выдай сообществу **доступ ко всей переписке**: по умолчанию бот видит только упоминания, а короткие команды вроде `+` без этого доступа не прочитает. Выдать доступ может любой администратор беседы (список участников → сообщество → права).

#### 5. CHAT_PEER_ID

В `.env` нужен **ID беседы, полученный от имени того же сообщества, чей
VK_TOKEN использует бот**. Число из URL беседы в личном аккаунте нельзя
без проверки переносить в настройки сообщества: это другой контекст доступа.
Надёжный способ — получить `peer_id` из нового события `message_new`
непосредственно в нужной беседе.

В проекте есть утилита [`src/vk_ids.py`](src/vk_ids.py). Она читает `VK_TOKEN`
из `.env` (переменная окружения имеет приоритет) и не требует уже известного
`CHAT_PEER_ID`. Команды ниже одинаковы для PowerShell, Bash и терминала IDE.
Утилита не запускает планировщик, не отправляет ответы в чат и не меняет `.env`
или список участников.

1. Выполни `uv sync` из корня проекта. Создай `.env` из `.env.example`
   и заполни **VK_TOKEN нужного сообщества**. Пока оставь `CHAT_PEER_ID`
   из примера или удали строку: для утилиты это значение не используется.
2. Добавь **это сообщество** в нужную беседу, включи Long Poll API и событие
   **Входящее сообщение (`message_new`)**, выдай доступ ко всей переписке
   (шаги 1, 2 и 4 выше).
3. Останови запущенные экземпляры обычного бота, включая Docker/сервер.
   На время проверки используй только утилиту, чтобы избежать параллельного
   опроса и ответов основного бота.
4. Запусти из корня проекта:

   ```bash
   uv run python -m src.vk_ids chat
   ```

5. Дождись строки **«Готово»**. Проверь показанные имя и ID сообщества.
   Скопируй выданную метку вида `vk-peer-a1b2c3d4e5f6` и отправь её
   **новым обычным сообщением от своего личного аккаунта в нужную беседу**.
   Не отправляй её в личные сообщения сообщества, не пересылай другое сообщение
   и не используй метку из предыдущего запуска. Каждая метка уникальна;
   имя беседы не используется, поэтому одинаковые названия не мешают проверке.
6. Утилита напечатает, например:

   ```text
   CHAT_PEER_ID=2000000042
   VK ID автора проверочного сообщения: 123456789
   ```

   Скопируй **своё фактическое значение** `CHAT_PEER_ID` в `.env`.
   Прибавлять `2000000000` к результату не нужно. Утилита завершится сама.
7. Запусти бота: `uv run python -m src.main`. Напиши `помощь` в той же беседе:
   бот должен показать карточку. Если запускаешь Docker/облако, обнови
   переменную и там; для Compose пересоздай контейнер командой
   `docker compose up -d --force-recreate`, чтобы он перечитал `.env`.

По умолчанию ожидание — 180 секунд. Можно увеличить:

```bash
uv run python -m src.vk_ids chat --timeout 600
```

Если результата нет, проверь по порядку:

- В терминале показано нужное сообщество; в окружении нет старого `VK_TOKEN`,
  который перекрывает `.env`.
- Сообщество действительно состоит в беседе и видит всю переписку.
- Long Poll включён, отмечено `message_new`, изменения сохранены;
  токен сообщества имеет доступ к сообщениям.
- Новая метка отправлена после «Готово», без дополнительных слов или упоминаний,
  именно в беседу, от пользователя. Личные сообщения утилита игнорирует.
- При ошибке авторизации проверь, что ключ действителен и принадлежит сообществу;
  при сетевой ошибке повтори запуск. `Ctrl+C` отменяет ожидание.

**Что с прежними способами?**

| Способ | Ограничения |
|---|---|
| Число из URL личного аккаунта | Не подтверждает ID, который получает сообщество; не использовать как основной способ |
| Пересылка сообщения в личку сообщества | `peer_id` внешнего сообщения относится к личному диалогу. Поле исходного peer в пересланном объекте необязательное; интерфейс не обязан показывать его |
| `2000000000 + chat_id` | Формула верна только для `chat_id`, уже полученного в контексте нужного сообщества; сама по себе не находит беседу |
| `messages.getConversations` | Метод поддерживает токены сообществ. Ищи только `peer.type="chat"` и `conversation.peer.id`; учитывай страницы `offset/count` (по умолчанию всего 20 диалогов). Пустой результат не заменяет проверку по новому сообщению |

Схемы VK: [методы messages](https://github.com/VKCOM/vk-api-schema/blob/master/messages/methods.json),
[объекты сообщений и пересылок](https://github.com/VKCOM/vk-api-schema/blob/master/messages/objects.json).

#### 6. VK ID администраторов

`ADMIN_VK_IDS_RAW` — **положительные числовые ID личных аккаунтов** через
запятую. Права администратора беседы или сообщества сами по себе не дают
доступ к админ-командам бота: пользователь должен быть указан в этой переменной.

Если адрес профиля имеет вид `https://vk.com/id123456789`, его ID — `123456789`.
Если вместо числа короткое имя, например `https://vk.com/alex_volley`, получи
ID через ту же утилиту. Можно передать несколько профилей за один запуск:

```bash
uv run python -m src.vk_ids users "https://vk.com/alex_volley" "id987654321"
```

Поддерживаются прямые ссылки на профили `vk.com`/`vk.ru`, короткие имена,
`id123456789` и числа. Команда использует официальный `users.get` с тем же
токеном сообщества; Long Poll и остановка основного бота для неё не нужны.
Она показывает имя и фамилию для проверки личности и готовую строку:

```text
alex_volley: Александр Иванов — 123456789
987654321: Иван Петров — 987654321

ADMIN_VK_IDS_RAW=123456789,987654321
```

Имена и числа здесь — примеры. Убедись, что найдены нужные люди, затем вставь
выданную строку в `.env` и перезапусти бота (для Compose — пересоздай контейнер).
В нужной беседе выполни `админ помощь` от каждого добавленного аккаунта.
Не вставляй ссылки, короткие имена, ID сообщества, `CHAT_PEER_ID` или пустые
элементы вида `123,,456`. Пустое значение отключает доступ всем администраторам.

Ещё один способ получить **свой** ID — строка «VK ID автора проверочного
сообщения» после команды `chat`: это ID аккаунта, который отправил метку.
Для ID других людей используй `users`, чтобы не перепутать автора сообщения.
См. [схему `users.get`](https://github.com/VKCOM/vk-api-schema/blob/master/users/methods.json).

## Команды бота

Текстовые команды принимаются независимо от регистра и пробелов по краям:
например, `Записаться`, `  СПИСОК  `, `Создать событие ...`.
В командах для друзей регистр имени сохраняется.

| Команда | Описание |
|---|---|
| `записаться` | Записать себя |
| `отписаться` | Убрать себя |
| `+` | Подсказка, как записаться (не добавляет вас) |
| `+ Имя` | Записать друга, пока запись открыта |
| `- Имя` | Убрать друга |
| `список`, `участники`, `кто идёт` | Показать актуальную карточку в конце чата |
| `?`, `help`, `помощь`, `команды` | Справка |
| `создать событие ДД.ММ.ГГГГ ЧЧ:ММ` | Открыть ручное событие (только админ) |
| `статус события` | Показать состояние, начало и VK ID карточки (только админ) |

В чате поддерживается одна карточка события с inline-клавиатурой:
**✅ Записаться**, **↩️ Отписаться**, **❓ Помощь**. После
обработанной текстовой команды бот публикует актуальную карточку последним
сообщением и удаляет предыдущую. Кнопки обновляют карточку на месте и отвечают
через snackbar, не создавая новых сообщений.

### Когда открывается запись

`COLLECT_WEEKDAY` и `COLLECT_TIME` задают еженедельный анонс, а
`EVENT_WEEKDAY` и `EVENT_TIME` — начало тренировки. Значения считаются в
локальном времени сервера; образ Docker использует `Europe/Moscow`. По
умолчанию анонс выходит в понедельник в 08:00, тренировка начинается во
вторник в 19:30.

В назначенный момент бот:

1. временно переводит регистрацию в состояние `opening`, запрещая новые записи
   и сохраняя участников предыдущего сбора;
2. отправляет в чат анонс нового сбора;
3. только после успешной отправки и сохранения состояния очищает прежний список
   и переводит регистрацию в `open`.

Именно завершение третьего шага открывает команды `записаться`, `+ Имя` и
кнопку **✅ Записаться**. Если VK временно недоступен, бот повторяет отправку
через пять минут, а запись остаётся недоступной. В момент `EVENT_*` бот
автоматически закрывает запись, сохраняет итоговый список и редактирует
существующую карточку без нового сообщения в чат.

В первые 30 минут после начала можно отписаться: имя остаётся в конце списка
с `(-)`, а счётчик участников уменьшается. Повторная запись в этот период
снимает минус и возвращает имя выше отписавшихся. Это действует и для друзей
через `- Имя` / `+ Имя`. Новые участники после начала не добавляются.
Ровно через 30 минут отписка и возврат блокируются. До начала отписка
удаляет имя из списка полностью.

Если бот был выключен в запланированное время, пропущенный сбор автоматически
не запускается — планировщик ждёт следующую неделю. Исключение: сохранённое
состояние `opening` после прерванного анонса возобновляется сразу при старте.
Если сохранённое время начала уже прошло, запись закрывается без позднего
анонса.

Администратор может в любое время отправить
`создать событие ДД.ММ.ГГГГ ЧЧ:ММ`. Анонс публикуется сразу, а запись
закрывается в указанное время. Команда отклоняется, если запись уже открыта
или ручное событие пересекается со следующим еженедельным анонсом.

Подробности и примеры: [жизненный цикл регистрации](docs/BOT_COMMANDS.md#жизненный-цикл-регистрации)
и [настройка планировщика](docs/CONFIGURATION.md#настройка-планировщика).

### Админ-команды

Доступны только пользователям из `ADMIN_VK_IDS_RAW` (см. [`docs/CONFIGURATION.md`](docs/CONFIGURATION.md)):

| Команда | Описание |
|---|---|
| `удалить событие` | Отменить событие, очистить участников и удалить карточку |
| `очистить`, `сбросить` | Очистить список участников |
| `убрать Имя`, `удалить Имя` | Удалить участника по имени |
| `статус события` | Показать состояние, время начала, `message_id` и `conversation_message_id` |
| `админ помощь`, `admin help` | Справка в личном сообщении |

Все распознанные админ-команды удаляются для всех участников сразу после
получения, до выполнения действия, включая команды с ошибками и отказы в доступе.
Выдай сообществу **права администратора беседы**, иначе VK может запретить
удаление сообщений участников. При отказе VK действие выполняется, а ошибка
удаления отправляется автору лично и записывается в журнал.

Справка, статус, подтверждение удаления события и ошибки отправляются автору
**в личные сообщения**, без добавления в общую карточку. Каждый администратор
должен открыть диалог с сообществом, отправить любое сообщение и разрешить
сообщения от него. Если VK запрещает личную доставку, ошибка будет в журнале;
справка в беседе не публикуется.

`удалить событие` работает для открытого, закрытого и ещё публикуемого события.
Удаление отменяет его отложенный анонс и автоматическое закрытие. Еженедельное
расписание остаётся включённым. Если VK не удалил карточку, событие всё равно
отменяется, а её ID сохраняются для повторной команды удаления.

## Разработка

Перед разработкой прочитайте [Piecemeal Growth](docs/mode-piecemeal-growth.md)
и [Focused Specs](docs/focused-specs.md), затем следуйте
[процессу проекта](docs/DEVELOPMENT.md). Приложение должно соответствовать BDD;
все изменения выполняются в отдельной ветке. Правила агента и полный список
актуальных документов находятся в [AGENTS.md](AGENTS.md).

```bash
# Линтер и форматтер
uv run ruff check src tests
uv run ruff format --check src tests
uv run basedpyright

# Тесты и обязательный порог покрытия 80%
uv run pytest --cov=src --cov-report=term-missing

# Аудит зависимостей на известные CVE (шаг CI)
uv run pip-audit --desc

# Запуск локально
uv run python -m src.main

# Windows: фоновый запуск и остановка
powershell -ExecutionPolicy Bypass -File scripts/start_bot.ps1
powershell -ExecutionPolicy Bypass -File scripts/stop_bot.ps1

# Linux: фоновый запуск и остановка
bash scripts/start_bot.sh
bash scripts/stop_bot.sh
```

Скрипты выполняют `uv sync --frozen`, запускают бота в фоне и сохраняют PID в
`.run/bot.pid`. Запускай их из любой папки, указав путь к скрипту: `.env` и данные
читаются относительно корня проекта. Повторный запуск не создаёт второй экземпляр;
остановка уже завершённого бота удаляет устаревший PID. При повреждённом PID или
несовпадении процесса скрипт откажется работать — чужой процесс не завершается.

Логи: `logs/bot.stdout.log` и `logs/bot.stderr.log`. Linux дописывает логи,
Windows при новом запуске перезаписывает их; остановка оставляет логи и данные.
Linux отправляет `SIGTERM`, ждёт до 10 секунд и при необходимости использует
`SIGKILL`. Windows завершает всё дерево процесса Python принудительно.
Скрипты управления используют общую блокировку от одновременного запуска/остановки.

Для Linux нужны Bash, `uv` и `flock` (пакет `util-linux`), доступный `/proc` и
часовой пояс сервера `Europe/Moscow`. Запуск через `bash` не требует `chmod`.
Скрипты не обеспечивают автозапуск после перезагрузки: для этого используй
Docker или сервис systemd. Процесс, запущенный вручную через `uv run`, останавливай
в его терминале (`Ctrl+C`): он не имеет PID-файла этих скриптов. Если PID сохранён
старой версией скрипта запуска Windows (процесс `uv`), сначала останови прежний
экземпляр, проверь отсутствие бота и удали `.run/bot.pid` перед новым запуском.

## Troubleshooting

| Проблема | Решение |
|---|---|
| Бот не отвечает | Пройди чек-лист [Настройка сообщества VK](#настройка-сообщества-vk): сообщения включены, Long Poll API с событием `message_new`, бот добавлен в беседу с доступом ко всей переписке, в `CHAT_PEER_ID` указан `peer_id` (`2000000000 + chat_id`), а не `chat_id` |
| Кнопки не реагируют | В **Типы событий** Long Poll API не включено событие `message_event` |
| В логах ничего нет | Логи пишутся в stdout начиная со старта; проверь, что бот запущен и в `.env` заданы обязательные переменные |
| `ValidationError` | Не заданы обязательные переменные в `.env` |
| Scheduler не срабатывает | Проверь `COLLECT_*`, `EVENT_*` и часовой пояс |
| Данные теряются | Проверь `DATA_PATH` и volume (в Docker) |

# Проверка работоспособности

## Автоматические проверки

Все тесты работают без подключения к VK:

```bash
uv run --frozen ruff check src tests
uv run --frozen ruff format --check src tests
uv run --frozen basedpyright --level error
uv run --frozen pytest --cov=src --cov-report=term-missing
```

Покрытие должно быть не ниже 80%.

| Файл | Что проверяется |
|---|---|
| `tests/test_bot.py` | Формат карточки, клавиатура, справка и peer guard |
| `tests/test_bot_handlers.py` | Текстовые, callback и админские обработчики |
| `tests/test_cards.py` | Оба VK ID, замена/редактирование и сохранение рабочей карточки при ошибках |
| `tests/test_config.py` | Переменные окружения и коллизии расписания |
| `tests/test_scheduler.py` | Анонс, retry, ручное событие, восстановление и закрытие |
| `tests/test_storage.py` | JSON, атомарность, снимки, конкурентность и лимиты |
| `tests/test_smoke.py` | Сборка `main()` и параллельный запуск задач |

## Надёжный локальный запуск в Windows

Заполните `.env`, затем запустите скрытый длительный процесс:

```powershell
uv sync
powershell -ExecutionPolicy Bypass -File scripts/start_bot.ps1
```

Скрипт сохраняет:

- PID: `.run/bot.pid`;
- стандартный вывод: `logs/bot.stdout.log`;
- журнал и ошибки: `logs/bot.stderr.log`.

Проверка:

```powershell
$botPid = [int](Get-Content .run/bot.pid -Raw)
Get-Process -Id $botPid
Get-Content logs/bot.stderr.log -Tail 50
```

В журнале должны появиться `Config loaded`, `Scheduler started` и
`Next scheduler action`. Повторный запуск скрипта не создаёт второй процесс,
пока сохранённый PID работает.

## Ручной приёмочный тест закрытия

1. Запустите бота через `scripts/start_bot.ps1` и убедитесь, что PID жив.
2. Создайте событие на 3–5 минут вперёд:

   ```text
   создать событие ДД.ММ.ГГГГ ЧЧ:ММ
   ```

3. Проверьте карточку: полная дата, время начала, `запись открыта`, пустой или
   актуальный список и четыре кнопки.
4. Выполните `записаться`, `+ Друг`, `список`. После каждой текстовой команды в
   чате должна оставаться одна карточка бота и она должна быть последней.
5. Нажмите кнопки записи, списка и помощи. Новых сообщений быть не должно;
   результат показывается snackbar, список меняется в карточке.
6. Отправьте `статус события` от администратора. В карточке должны быть
   `state=open`, время начала и хотя бы один положительный VK ID.
7. Не останавливайте процесс до начала события. В назначенную минуту проверьте:
   - в `data.json` записано `registration_state: "closed"`;
   - `event_starts_at` сохранён;
   - карточка показывает `запись закрыта` и итоговый список;
   - команда `записаться` не меняет список, причина появляется в карточке;
   - в журнале есть переход `open/opening -> closed`.

## Проверка перезапуска

Создайте событие через 5 минут, завершите процесс по PID, снова запустите
`scripts/start_bot.ps1` до начала и убедитесь, что закрытие происходит вовремя.
Отдельно можно запустить бот уже после сохранённого дедлайна: состояние должно
сразу стать `closed`, без позднего анонса.

## Ожидаемая карточка

```text
🏐 Волейбол — запись открыта
📅 Вторник, 22 сентября 2026
🕢 Начало: 19:30
⏳ Запись закроется автоматически в 19:30

Участники: 2
1. Александр
2. Петя (друг)
```

После закрытия строка с таймером исчезает, участники остаются.

## Docker

```bash
docker compose up -d --build
docker compose logs -f vk-bot
docker compose ps
```

Контейнер должен быть `running`, healthcheck — `healthy`. Данные сохраняются в
volume, поэтому перезапуск контейнера не должен терять дедлайн или участников.

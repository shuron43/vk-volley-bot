# Проверка работоспособности

## Автоматические проверки

Все тесты работают без подключения к VK:

```bash
uv run --frozen ruff check src tests
uv run --frozen ruff format --check src tests
uv run --frozen basedpyright
uv run --frozen pytest --cov=src --cov-report=term-missing
```

Покрытие должно быть не ниже 80%.

| Файл | Что проверяется |
|---|---|
| `tests/test_bot.py` | Формат карточки, клавиатура, справка и peer guard |
| `tests/test_bot_handlers.py` | Бизнес-исходы текстовых, callback и админских команд через настоящий роутер |
| `tests/test_cards.py` | Оба VK ID, замена/редактирование и сохранение рабочей карточки при ошибках |
| `tests/test_config.py` | Переменные окружения и коллизии расписания |
| `tests/test_scheduler.py` | Анонс, retry, ручное событие, восстановление и закрытие |
| `tests/test_storage.py` | JSON, атомарность, снимки, конкурентность и лимиты |
| `tests/test_late_withdrawal.py` | Откат поздних изменений при ошибке диска и закрытое состояние без дедлайна |
| `tests/test_vk_ids.py` | Получение конфигурационных ID, восстановление Long Poll и освобождение HTTP-сессии |
| `tests/test_smoke.py` | Сборка `main()` и параллельный запуск задач |

Бизнес-спеки в `tests/test_bot_handlers.py` следуют
[Focused Specs](focused-specs.md): исходное состояние в `Given`, один запрос
в `When` и один пользовательский или сохраняемый исход в `Then`.
Все команды передаются как `message_new` в настоящий маршрутизатор VKBottle.
Кнопки передаются как `message_event` с payload из фактической клавиатуры.
Подменяется только внешний VK API; хранилище JSON, издатель карточек и создание
события выполняют настоящий код. Результат читается новым экземпляром `Storage`
и проверяется на границе отправки, редактирования, удаления или snackbar VK.

- `test_participant_presses_signup`, `test_registered_participant_presses_withdrawal`
  и `test_participant_presses_help` защищают маршрутизацию всех трёх кнопок;
- `test_admin_creates_manual_event` подтверждает сохранение открытого ручного
  события и публикацию карточки с допустимым дедлайном до недельного анонса;
- отдельные сценарии админа защищают очистку списка, удаление участника,
  приватность справки/диагностики и порядок удаления команды перед карточкой;
- `test_unlisted_participant_is_denied_admin_command` проверяет прямой отказ
  постороннему и отказ бывшему админу при пустом `ADMIN_VK_IDS_RAW`;
- сценарии чужой беседы доставляют текстовые команды и настоящие callback payload;
- самостоятельные сценарии отписки и возврата сохраняют проверки временных
  границ: до начала, начало, 29:59, 30:00 и после окна, для обеих интерфейсных
  форм пользователя и для текстовых команд друга.

Регистры команд, алиасы и пробелы проверяются параметризацией одного запроса.
Клавиатура проверяется по смыслу доступных действий и inline-режиму, без
фиксирования цветов, эмодзи и раскладки. Технические тесты отдельно защищают
атомарную запись, перезапуск, протокол Long Poll и закрытие HTTP-сессии.
Порядок разработки, ревью и ведения знаний описан в
[DEVELOPMENT.md](DEVELOPMENT.md).

`test_manual_event_wakes_sleeping_scheduler_and_closes_actual_card_on_time`
в `tests/test_scheduler.py` воспроизводит создание ручного события во время
ожидания еженедельного анонса. Проверяется новый дедлайн и фактический текст
редактирования VK: «запись закрыта», без строки «закроется автоматически»,
с сохранёнными участниками и без нового сообщения.

## Надёжный локальный запуск в Windows

Заполните `.env`, затем запустите скрытый длительный процесс:

```powershell
uv sync
powershell -ExecutionPolicy Bypass -File scripts/start_bot.ps1
```

Скрипт сохраняет:

- PID: `.run/bot.pid`;
- стандартный вывод: `logs/bot.stdout.log`;
- журнал и ошибки: `logs/bot.stderr.log`.

Проверка:

```powershell
$botPid = [int](Get-Content .run/bot.pid -Raw)
Get-Process -Id $botPid
Get-Content logs/bot.stderr.log -Tail 50
```

В журнале должны появиться `Config loaded`, `Scheduler started` и
`Next scheduler action`. Повторный запуск скрипта не создаёт второй процесс,
пока сохранённый PID работает.

## Ручной приёмочный тест закрытия

Автоматические BDD-сценарии в `tests/test_late_withdrawal.py` проверяют границы
30-минутного окна, порядок имён и `(-)`, возврат, сохранение после перезапуска
и откат при ошибке диска. Сценарии в `tests/test_bot_handlers.py` проверяют
те же действия через зарегистрированные текстовые и callback-обработчики.

После начала тестового события проверьте отписку и возврат: имя должно сначала
оказаться внизу с `(-)`, затем вернуться выше отписавшихся без минуса. Счётчик
участников должен уменьшиться и восстановиться. Повторите для `- Друг` / `+ Друг`.
Новый участник в этот период записаться не должен. Через 30 минут от начала
отписка и возврат должны выдавать отказ и сохранять список.

1. Запустите бота через `scripts/start_bot.ps1` и убедитесь, что PID жив.
2. Создайте событие на 3–5 минут вперёд:

   ```text
   создать событие ДД.ММ.ГГГГ ЧЧ:ММ
   ```

3. Проверьте карточку: полная дата, время начала, `запись открыта`, пустой или
   актуальный список и три кнопки: «Записаться», «Отписаться», «Помощь».
4. Выполните `записаться`, `+ Друг`, `список`. После каждой текстовой команды в
   чате должна оставаться одна карточка бота и она должна быть последней.
5. Нажмите кнопки записи, отписки и помощи. Новых сообщений быть не должно;
   результат показывается snackbar, список меняется в карточке. Помощь
   объясняет: `список — показать актуальную карточку в конце чата`.
6. Отправьте `статус события` от администратора. Команда должна исчезнуть из
   беседы; в личном сообщении должны быть состояние `open`, время начала и VK ID.
   Проверьте `админ помощь`: справка приходит лично, карточка не меняется.
7. Не останавливайте процесс до начала события. В назначенную минуту проверьте:
   - в `data.json` записано `registration_state: "closed"`;
   - `event_starts_at` сохранён;
   - карточка показывает `запись закрыта` и итоговый список;
   - команда `записаться` не меняет список, причина появляется в карточке;
   - в журнале есть переход `open/opening -> closed`.

## Проверка перезапуска

Создайте событие через 5 минут, завершите процесс по PID, снова запустите
`scripts/start_bot.ps1` до начала и убедитесь, что закрытие происходит вовремя.
Отдельно можно запустить бот уже после сохранённого дедлайна: состояние должно
сразу стать `closed`, без позднего анонса.

## Ожидаемая карточка

```text
🏐 Волейбол — запись открыта
📅 Вторник, 22 сентября 2026
🕢 Начало: 19:30
⏳ Запись закроется автоматически в 19:30

Участники: 2
1. Александр
```

После закрытия строка с таймером исчезает, участники остаются.

## Docker

```bash
docker compose up -d --build
docker compose logs -f vk-bot
docker compose ps
```

Контейнер должен быть `running`, healthcheck — `healthy`. Данные сохраняются в
volume, поэтому перезапуск контейнера не должен терять дедлайн или участников.

## Удаление события и приватность админ-команд

BDD в `tests/test_bot_handlers.py` проходят через настоящий Long Poll роутер:
все админ-команды с разным регистром и пробелами удаляются для всех, справка и
ошибки уходят лично, посторонняя беседа игнорируется. Проверяется порядок:
сначала удаляется команда, затем событие и его карточка. Отказы в личной доставке
не приводят к публикации справки в беседе.

`tests/test_cards.py` проверяет отмену на этапах `opening`, `open`, `closed`,
перезапуск, сигнал пересчёта расписания, запрет повторной отправки отменённого
анонса, ошибки записи файла и удаления карточки в VK.

Для ручной проверки создай тестовое событие и отправь `Удалить событие`:
команда и карточка должны исчезнуть, подтверждение — прийти лично; после
перезапуска участники и отменённое событие не возвращаются. Следующий еженедельный
анонс продолжает работать.

## Скрипты запуска и остановки

На Linux проверку можно выполнить без токена VK и настройки `.env`:

```bash
bash -n scripts/bot_common.sh scripts/start_bot.sh scripts/stop_bot.sh tests/test_process_scripts.sh
bash tests/test_process_scripts.sh
```

Этот тест создаёт временный проект с простым процессом Python и подменяет только
`uv sync`. Проверяет запуск из другой папки и пути с пробелами, повторный запуск,
остановку, устаревший/повреждённый PID, отказ завершать чужой процесс, сохранение
логов и сбой при старте. Исходные данные проекта и VK API не используются.
Проверка запускается также в GitHub Actions на Ubuntu.

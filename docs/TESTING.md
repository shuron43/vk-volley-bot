## Автотесты (без VK API)

Тесты запускаются без подключения к VK — используют моки, временные файлы и детерминированное время.

```bash
uv run pytest --cov=src --cov-report=term-missing
```

### Что проверяют тесты

| Файл | Что проверяется |
|------|-----------------|
| `tests/test_smoke.py` | Импорты и корректность сборки `main()`: Config → Storage → Bot → Scheduler |
| `tests/test_bot.py` | Форматирование, клавиатура и запрет обработки событий из чужого peer |
| `tests/test_bot_handlers.py` | Зарегистрированные text/callback/admin handlers через реальный временный `Storage` |
| `tests/test_config.py` | Формат времени, коллизии расписания, `peer_id`, путь и ранний разбор admin ID |
| `tests/test_scheduler.py` | Расчёт событий, напоминание, retry и единственная очистка на один сбор |
| `tests/test_storage.py` | JSON round-trip, транзакционность при ошибке записи, конкурентность и лимиты |

Порог покрытия задан в `pyproject.toml` и равен 80%; команда завершится с ошибкой,
если тесты проходят, но покрытие ниже порога.

## Локальный запуск

Минимальные требования: заполненный `.env` с `VK_TOKEN` и `CHAT_PEER_ID`.

```bash
uv sync
cp .env.example .env
# Отредактируй .env: VK_TOKEN, CHAT_PEER_ID
uv run python -m src.main
```

### Признаки корректного старта

- Бот **не падает** с `ValidationError` → `.env` корректен.
- В логах нет ошибок подключения к VK → токен валиден.
- В VK-чате бот **онлайн** (зелёная точка у сообщества, если включён статус).

### Остановка

`Ctrl+C` — корректно завершает polling и scheduler через `anyio` TaskGroup.

## Ручная проверка в VK

Напишите в групповой чат (тот, что указан в `CHAT_PEER_ID`):

### Текстовые команды

| Команда | Ожидаемый результат |
|---------|---------------------|
| `записаться` | "Ты записался!" или "Ты уже в списке." При закрытой регистрации — "Запись закрыта. Дождись следующего анонса или нажми «Помощь»." |
| `+` или `+   ` | Подсказка `Чтобы записаться, нажми «Записаться» или напиши «записаться» после анонса. Для друга: + Имя.` Список не меняется в любом состоянии |
| `-` или `отписаться` | "Ты отписался." или "Тебя не было в списке." |
| `+ Андрей` | "Андрей записан(а) как друг." При закрытой регистрации — "Запись закрыта. Дождись следующего анонса или нажми «Помощь»." |
| `- Андрей` | "Андрей убран(а) из списка." или "Такого друга не нашлось." |
| `список` | Нумерованный список участников или "Пока никто не записался." Работает в любом состоянии |
| `?` | Справка по командам (единый текст с кнопкой **❓ Помощь**) |

### Inline-клавиатура

Под каждым ответом бота есть кнопки:

```
✅ Записаться   ↩️ Отписаться
📋 Список      ❓ Помощь
```

| Кнопка | Ожидаемый результат |
|--------|---------------------|
| `✅ Записаться` | Snackbar "Ты записался!" / "Ты уже в списке." / "Запись закрыта...". При успешной записи канонический статус бота обновляется через `messages.edit` |
| `↩️ Отписаться` | Snackbar "Ты отписался." / "Тебя не было в списке." При успешной отписке канонический статус бота обновляется через `messages.edit` |
| `📋 Список` | Бот пытается отредактировать то сообщение, к которому привязана кнопка. При успехе — snackbar "Список обновлён в сообщении бота." При отказе VK — одно заменяющее сообщение со списком |
| `❓ Помощь` | Бот пытается отредактировать то сообщение, к которому привязана кнопка. При успехе — snackbar "Справка обновлена." При отказе VK — одно заменяющее сообщение со справкой |

### Полный сценарий проверки (после анонса)

```
Вы: записаться
Бот: Ты записался!

Вы: список
Бот:
Список участников:
1. Ваше имя

Вы: + Мария
Бот: Мария записан(а) как друг.

Вы: список
Бот:
Список участников:
1. Ваше имя
2. Мария (друг)

Вы: -
Бот: Ты отписался.

Вы: - Мария
Бот: Мария убран(а) из списка.

Вы: список
Бот: Пока никто не записался.
```

> **Проверка scheduler'а:** дождитесь анонса (`COLLECT_*`) и убедитесь, что карточка содержит начало из `EVENT_*`. В момент начала запись должна перейти в `closed`, итоговый список сохраниться, а карточка обновиться без нового сообщения. При временной ошибке VK повтор ограничен временем начала.

### Ручной смоук-сценарий по жизненному циклу

Сценарий покрывает переходы между состояниями регистрации, безопасный `+`,
запись друга через текстовую команду и работу callback-кнопок.

```
=== До анонса (registration_state=closed) ===

Вы: записаться
Бот: Запись закрыта. Дождись следующего анонса или нажми «Помощь».

Вы: +
Бот: Чтобы записаться, нажми «Записаться» или напиши «записаться» после анонса. Для друга: + Имя.

Вы: + Андрей
Бот: Запись закрыта. Дождись следующего анонса или нажми «Помощь».

Вы: список
Бот: Пока никто не записался.

Вы: -
Бот: Тебя не было в списке.

Вы: ?
Бот: Запись открывается после анонса и закрывается в момент начала события. ...

=== После анонса (registration_state=open) ===

Бот: 🏐 Запись на волейбол открыта! 🗓 Начало: ...

Вы: записаться
Бот: Ты записался!

Вы: +
Бот: Чтобы записаться, нажми «Записаться» или напиши «записаться» после анонса. Для друга: + Имя.
[Список НЕ изменился — `+` всегда подсказка]

Вы: + Мария
Бот: Мария записан(а) как друг.

Вы: записаться
Бот: Ты уже в списке.

=== Callback-кнопки ===

Вы: [жмёт 📋 Список у анонса]
Чат: (новых сообщений нет)
[У автора нажатия — snackbar "Список обновлён в сообщении бота."]
Бот (то же сообщение анонса): Список участников: 1. Ваше имя 2. Мария (друг)

Вы: [жмёт ❓ Помощь у анонса]
Чат: (новых сообщений нет)
[У автора нажатия — snackbar "Справка обновлена."]
Бот (то же сообщение анонса): Запись открывается после анонса сбора. ...

Вы: [жмёт ✅ Записаться у анонса]
Чат: (новых сообщений нет)
[У автора нажатия — snackbar "Ты уже в списке."]

Вы: [жмёт ↩️ Отписаться у анонса]
Чат: (новых сообщений нет)
[У автора нажатия — snackbar "Ты отписался."]
Бот (то же сообщение анонса): Список участников: 1. Мария (друг)
```

Что проверяет сценарий:

| Шаг | Что подтверждает |
|-----|------------------|
| `+` до анонса | `+` не мутирует список, не зовёт VK API |
| `записаться` / `+ Имя` до анонса | Закрытая регистрация даёт отказ без побочных эффектов |
| `список`, `?`, `-` до анонса | Эти команды работают в любом состоянии |
| `+` после анонса | `+` остаётся подсказкой даже при открытой записи |
| Callback `📋 Список` / `❓ Помощь` | Сообщение бота редактируется, чат не получает нового сообщения |
| Callback `✅ Записаться` / `↩️ Отписаться` | Snackbar у нажавшего + `messages.edit` канонического статуса |

## Docker

### Сборка и запуск

```bash
docker build -t vk-volleyball-bot .
docker run -d --env-file .env -v vk-bot-data:/app/data --restart unless-stopped vk-volleyball-bot
# или
docker compose up -d
```

### Проверка контейнера

```bash
# Статус и health
docker ps
# или
docker compose ps

# Логи в реальном времени
docker compose logs -f

# Проверка записи данных
docker exec vk-volleyball-bot test -w /app/data && echo "OK" || echo "FAIL"
```

### Что означает `healthy`

Docker healthcheck проверяет только, что volume `/app/data` доступен для записи. Это **не** гарантирует, что бот подключён к VK или polling работает. Для полной проверки используйте ручные команды в чате (см. выше).

## Ограничения проверки без VK API

| Что проверить | Без VK API | Нужен VK API |
|---------------|------------|--------------|
| Конфиг, storage, форматирование | ✅ Тесты | ❌ Нет |
| Логика scheduler'а | ✅ Тесты | ❌ Нет |
| Сборка `main()` | ✅ Тесты | ❌ Нет |
| Подключение к VK | ❌ Нет | ✅ Локальный запуск |
| Отправка сообщений | ❌ Нет | ✅ Ручная проверка |
| Подтягивание имени через `users.get` | ❌ Нет | ✅ `записаться` или кнопка **✅ Записаться** |
| Inline-кнопки | ❌ Нет | ✅ Нажатие в чате |

Полноценного HTTP health endpoint в коде нет. Контейнерный healthcheck лишь проверяет права на файловую систему.

## Чеклист "Бот работает за 5 минут"

- [ ] `uv run pytest --cov=src --cov-report=term-missing` — тесты проходят, покрытие не ниже 80%.
- [ ] `.env` заполнен: `VK_TOKEN`, `CHAT_PEER_ID`.
- [ ] `uv run python -m src.main` — бот стартует без ошибок.
- [ ] В VK-чате: `?` → показывает справку.
- [ ] В VK-чате: `+` → подсказка, а не запись.
- [ ] В VK-чате: `список` → показывает список.
- [ ] После планового анонса регистрация открыта: `записаться` и `+ Имя` добавляют участников.
- [ ] Inline-кнопки `✅ Записаться`, `↩️ Отписаться`, `📋 Список`, `❓ Помощь` — работают; нажатие **📋 Список**/**❓ Помощь** редактирует исходное сообщение, а не создаёт новое.

Если все пункты отмечены — бот полностью работоспособен.

## Troubleshooting при проверке

| Проблема | Причина | Решение |
|----------|---------|---------|
| `pytest` падает на импортах | Не установлены зависимости | `uv sync` |
| `ValidationError` при старте | `.env` неполный или невалидный | Проверь токен, peer, формат времени, несовпадение расписаний и `ADMIN_VK_IDS_RAW` |
| Бот стартует, но не отвечает в чате | Неправильный `CHAT_PEER_ID` или токен без прав `messages` | Перепроверь `peer_id` и права токена |
| `записаться` возвращает «Не удалось получить данные из VK» | VK API недоступен или токен без `users` | Проверь токен и права. `+` подсказку не должен задевать — он не обращается к VK API |
| Scheduler не срабатывает | Неправильный часовой пояс или время | Проверь `TZ` (Docker) или системное время |
| Данные теряются после перезапуска | Неправильный `DATA_PATH` или отсутствует volume | Локально — `data.json` в cwd; Docker — `/app/data/participants.json` с volume |

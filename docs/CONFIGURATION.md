# Конфигурация

## Переменные окружения

Бот читает конфигурацию из файла `.env` (кодировка UTF-8) или напрямую из переменных окружения ОС.

### Обязательные переменные

| Переменная | Тип | Пример | Описание |
|------------|-----|--------|----------|
| `VK_TOKEN` | `str` | `vk1.a.xxx...` | Токен сообщества VK с правами **messages** и **manage** |
| `CHAT_PEER_ID` | `int` | `2000000001` | Положительный `peer_id` группового чата (`>= 1`) |

### Опциональные переменные

| Переменная | Тип | По умолчанию | Описание |
|------------|-----|--------------|----------|
| `COLLECT_WEEKDAY` | `int` (0–6) | `2` | День недели начала сбора: `0`=Понедельник, `6`=Воскресенье |
| `COLLECT_TIME` | `str` (HH:MM) | `10:00` | Локальное время сервера для анонса нового сбора. Валидируется: часы 0–23, минуты 0–59 |
| `REMIND_ENABLED` | `bool` | `true` | Включить напоминание перед сбором |
| `REMIND_WEEKDAY` | `int` (0–6) | `0` | День недели напоминания: `0`=Понедельник, `6`=Воскресенье |
| `REMIND_TIME` | `str` (HH:MM) | `08:00` | Локальное время напоминания. Тот же формат и валидация, что и `COLLECT_TIME`; при включённом напоминании момент не может совпадать со сбором |
| `ADMIN_VK_IDS_RAW` | `str` | `""` | Положительные VK ID администраторов через запятую. Парсится и валидируется при старте |
| `DATA_PATH` | `str` | `data.json` локально, `/app/data/participants.json` в Docker | Путь к JSON-файлу; компоненты `..` запрещены |

## Файл `.env.example`

```dotenv
VK_TOKEN=your_vk_group_token_here
CHAT_PEER_ID=2000000001
COLLECT_WEEKDAY=2
COLLECT_TIME=10:00
REMIND_ENABLED=true
REMIND_WEEKDAY=0
REMIND_TIME=08:00
ADMIN_VK_IDS_RAW=123456789,987654321
DATA_PATH=data.json
```

## Как получить VK_TOKEN

1. Откройте настройки вашего сообщества VK → **Работа с API** → **Ключи доступа**
2. Нажмите **Создать ключ**
3. Включите разрешения:
   - ✅ **Разрешить приложению управление сообществом**
   - ✅ **Разрешить приложению доступ к сообщениям сообщества**
4. Скопируйте токен и вставьте в `.env`

> ⚠️ **Важно:** Не коммитьте `.env` в git. Убедитесь, что `.env` добавлен в `.gitignore`.

## Как получить CHAT_PEER_ID

### Способ 1: через пересылку сообщения

1. Перешлите любое сообщение из группового чата в личные сообщения вашего сообщества
2. В теле пересланного сообщения VK покажет `peer_id`

### Способ 2: через API

```bash
printf 'access_token=%s&v=5.199' "$VK_TOKEN" \
  | curl -sS --data-binary @- https://api.vk.com/method/messages.getConversations
```

Найдите нужный чат в `response.items[].conversation.peer.id`.

### Формула

```
peer_id = 2000000000 + chat_id
```

Например, если `chat_id = 1`, то `peer_id = 2000000001`.

## Настройка планировщика

### Валидация COLLECT_TIME

Формат строго `HH:MM` (двузначные часы и минуты, разделённые `:`):
- Часы: `00` – `23`
- Минуты: `00` – `59`

Невалидные значения вызовут `ValidationError` при старте:
- `25:00` — часы вне диапазона
- `10:70` — минуты вне диапазона
- `10:5` — минуты должны быть двузначными
- `10-00` — разделитель должен быть `:`

### Примеры

| COLLECT_WEEKDAY | COLLECT_TIME | Результат |
|-----------------|--------------|-----------|
| `2` | `10:00` | Каждую среду в 10:00 |
| `4` | `19:30` | Каждую пятницу в 19:30 |
| `0` | `09:00` | Каждый понедельник в 09:00 |
| `6` | `12:00` | Каждое воскресенье в 12:00 |

### Напоминание перед сбором

Бот может отправлять напоминание в заданный день недели и время — например, за день до сбора (или в любой другой день).

Напоминание содержит текущий список участников, чтобы люди видели, кто уже записался.

#### Валидация

`REMIND_TIME` использует те же правила, что и `COLLECT_TIME`:
- Формат `HH:MM` (двузначные часы и минуты)
- Часы: `00` – `23`, минуты: `00` – `59`

#### Примеры

| REMIND_WEEKDAY | REMIND_TIME | COLLECT_WEEKDAY | COLLECT_TIME | Результат |
|----------------|-------------|-----------------|--------------|-----------|
| `0` | `08:00` | `2` | `10:00` | Напоминание в понедельник 08:00, сбор в среду 10:00 |
| `1` | `18:00` | `3` | `19:00` | Напоминание во вторник 18:00, сбор в четверг 19:00 |
| — | — | `0` | `10:00` | Напоминание отключено (`REMIND_ENABLED=false`) |

> **Важно:** при `REMIND_ENABLED=true` одинаковые день и время напоминания и
> сбора запрещены. `Config` завершит запуск с `ValidationError`, чтобы ни одно
> еженедельное событие не потерялось.

### Валидация администраторов

`ADMIN_VK_IDS_RAW` допускает пустую строку или положительные целые VK ID через
запятую. Пробелы вокруг ID удаляются. Пустой элемент (`123,`), текст, `0` и
отрицательные ID вызывают `ValidationError` при старте; проверки прав во время
обработки команд уже работают с неизменяемым `tuple[int, ...]`.

### Часовой пояс

Планировщик использует **локальное время сервера** (`datetime.datetime.now()` без TZ).

Если сервер в UTC, а вы хотите анонс в 10:00 по Москве (UTC+3), укажите:
- `COLLECT_TIME=07:00` — для UTC-сервера
- Или настройте TZ сервера на нужный пояс

#### Docker / Linux

```bash
# Проверить текущий часовой пояс
date

# Установить Москву (для Debian/Ubuntu)
sudo timedatectl set-timezone Europe/Moscow
```

#### В Dockerfile

```dockerfile
ENV TZ=Europe/Moscow
RUN apt-get update && apt-get install -y --no-install-recommends tzdata \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*
```

Текущий образ устанавливает базу часовых поясов `tzdata` и задаёт `TZ`; это
соответствует корневому `Dockerfile`.

## Хранилище

### Размещение файла

По умолчанию `data.json` создаётся в рабочей директории бота.

При запуске через Docker рекомендуется:
- Установить `DATA_PATH=/app/data/participants.json` (и в `Dockerfile`, и в `docker-compose.yml`)
- Пробросить volume: `-v vk-bot-data:/app/data`
- Или монтировать директорию: `-v ./data:/app/data`

### Резервное копирование

Файл JSON — обычный текст. Копируйте его перед обновлениями:

```bash
cp data.json data.json.backup.$(date +%Y%m%d)
```

### Миграция данных

Если нужно перенести участников вручную, просто отредактируйте `data.json`:

```json
{
  "participants": [
    { "kind": "user", "vk_id": 123456789, "name": "Иван" },
    { "kind": "friend", "name": "Петр" }
  ],
  "registration_state": "closed",
  "status_message_id": null
}
```

Старые файлы только с полем `participants` тоже читаются: отсутствующие поля
получат значения `closed` и `null`. Для новых ручных переносов используйте
полную актуальную схему выше.

Файл читается **только при старте** (`Storage.__init__`). Если вы отредактируете JSON вручную во время работы бота, изменения будут перезаписаны при следующей операции записи из памяти. Чтобы применить ручные правки — перезапустите бот или добавьте участника через бот (это вызовет `_save()` с актуальным in-memory списком).

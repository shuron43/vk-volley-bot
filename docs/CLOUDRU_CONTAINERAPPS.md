# Деплой на cloud.ru Container Apps

Serverless-развёртывание VK Volleyball Bot без управления виртуальными машинами.

---

## Обзор

[cloud.ru Container Apps](https://cloud.ru/products/evolution-container-apps) — это serverless-платформа для запуска контейнеров без Kubernetes и ВМ. Вы загружаете Docker-образ в **Artifact Registry**, а платформа запускает его и следит за работой.

**Важный нюанс:** VK бот — это background worker (long-polling к VK API), а не web-сервис. Чтобы он работал 24/7, нужно настроить **минимум 1 "горячий" экземпляр** (min instances = 1). "Горячие" экземпляры остаются активными даже при отсутствии входящих HTTP-запросов.

> Образ запускается не от `root`, поэтому смонтированный `/app/data` должен быть writable для `botuser`. В качестве стартовой конфигурации ниже используются `256 MB RAM` и `0.1 vCPU`; после запуска проверьте метрики и увеличьте ресурсы при необходимости.

---

## Что понадобится

- Аккаунт cloud.ru с включённой платформой **Evolution**
- Docker на локальной машине для сборки образа
- Заполненный `.env` с `VK_TOKEN` и `CHAT_PEER_ID`

## Способ 1: Container Apps + Artifact Registry (рекомендуется)

### Шаг 1: Подготовка Docker-образа

Убедитесь, что в `Dockerfile` используется `ghcr.io/astral-sh/uv:python3.12-bookworm-slim` или аналогичный образ, и `CMD` запускает бота через модульный entrypoint:

```dockerfile
# Используем официальный образ uv с Python 3.12
FROM ghcr.io/astral-sh/uv:python3.12-bookworm-slim

# Установка часового пояса (опционально — измените TZ под ваш регион)
ENV TZ=Europe/Moscow
RUN apt-get update && apt-get install -y --no-install-recommends tzdata \
    && apt-get clean \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Создаём не-root пользователя и директорию для данных до COPY
RUN useradd --uid 1000 --create-home --home-dir /home/botuser --shell /usr/sbin/nologin botuser \
    && mkdir -p /app/data

# Копируем lock-файл и pyproject.toml первыми для оптимизации слоёв Docker
COPY --chown=botuser:botuser pyproject.toml uv.lock ./

# Устанавливаем production-зависимости (без dev-группы)
RUN uv sync --frozen --no-dev

# Копируем исходный код
COPY --chown=botuser:botuser src ./src

VOLUME ["/app/data"]

# По умолчанию внутри контейнера пишем в volume
ENV DATA_PATH=/app/data/participants.json

# Работаем не от root
USER botuser

# Проверяем, что volume с данными доступен для записи
HEALTHCHECK --interval=30s --timeout=5s --start-period=20s --retries=3 CMD test -w /app/data

# Запуск бота через uv run с модульным entrypoint
CMD ["uv", "run", "--no-sync", "python", "-m", "src.main"]
```

### Шаг 2: Сборка и пуш в Artifact Registry

```bash
# Создайте сервисный аккаунт с правами push/pull и выполните команду входа,
# которую показывает панель Artifact Registry
docker login <registry-host> -u <registry-user>

IMAGE_URI=<registry-host>/<project>/<repository>/vk-volleyball-bot:latest
docker build -t "$IMAGE_URI" .

# Пуш
docker push "$IMAGE_URI"
```

> URI и endpoint не составляйте вручную: скопируйте их из панели Artifact Registry.

### Шаг 3: Создание бакета в Object Storage для данных

VK бот пишет `data.json` при каждой записи/отписке. В Container Apps файловая система контейнера эфемерная, поэтому нужен **постоянный том**.

В cloud.ru Container Apps постоянный том — это бакет [Object Storage](https://cloud.ru/products/evolution-object-storage), смонтированный как директория. `DATA_PATH` должен ссылаться на файл внутри этого тома.

1. Панель управления → **Object Storage** → **Создать бакет**
2. Имя: `vk-bot-data-<уникальный_id>`
3. Класс: Стандарт
4. Доступ: Приватный

### Шаг 4: Создание Container App

Панель управления → **Container Apps** → **Container Services** → **Создать**.

#### Основные параметры контейнера

| Параметр | Значение | Пояснение |
|----------|----------|-----------|
| **Название** | `vk-volleyball-bot` | Глобально уникальное |
| **Конфигурация** | 0.1 vCPU — 256 MB RAM | Минимально достаточно для бота |
| **URI образа** | `cr.cloud.ru/.../vk-volleyball-bot:latest` | Из Artifact Registry |
| **Порт контейнера** | `8080` | Значение для обязательного поля; бот HTTP не слушает, публичный адрес не включайте |
| **Команда точки входа** | `uv` | Перезаписывает CMD образа |
| **Аргументы** | `run, --no-sync, python, -m, src.main` | Аргументы для команды |

> Примечание: если CMD задан в Dockerfile корректно, поля "Команда" и "Аргументы" можно оставить пустыми.

#### Переменные окружения

Добавьте все переменные из `.env`:

| Переменная | Значение |
|------------|----------|
| `VK_TOKEN` | `vk1.a.xxx...` |
| `CHAT_PEER_ID` | `2000000001` |
| `COLLECT_WEEKDAY` | `0` |
| `COLLECT_TIME` | `08:00` |
| `EVENT_WEEKDAY` | `1` |
| `EVENT_TIME` | `19:30` |
| `DATA_PATH` | `/app/data/participants.json` |
| `TZ` | `Europe/Moscow` |

> **Важно:** `DATA_PATH` должен указывать на файл внутри смонтированного тома (`/app/data/participants.json`), а не на локальный путь из `.env.example`.

#### Health-проба

VK бот — не HTTP-сервис, поэтому используйте **exec-пробу**:

- **Способ запуска:** `exec`
- **Команда:** `test -w /app/data`
- **Начальная задержка:** `30` секунд (время запуска бота)
- **Частота:** `60` секунд
- **Таймаут:** `10` секунд
- **Количество неуспешных проб:** `3`

> Эта проба проверяет, что `/app/data` доступен на запись. Если том не примонтирован или права сломаны, ревизия будет unhealthy.

#### Том (Volume) для данных

В разделе **Тома** → **Добавить постоянный том**:

| Параметр | Значение |
|----------|----------|
| **Бакет** | `vk-bot-data-<уникальный_id>` |
| **Путь** | `/app/data` |
| **Только чтение** | Выключено |

> Путь `/app/data` внутри контейнера монтируется к бакету Object Storage. После
> первого запуска обязательно проверьте запись и повторное чтение
> `participants.json`: `Storage` использует временный файл и `replace()`, поэтому
> том должен поддерживать эти файловые операции. Если проверка не проходит,
> используйте VM + Docker Compose из [CLOUDRU.md](CLOUDRU.md).

#### Масштабирование (критически важно)

| Параметр | Значение | Пояснение |
|----------|----------|-----------|
| **Мин. количество экземпляров** | `1` | Обязательно! Горячий экземпляр работает 24/7 |
| **Макс. количество экземпляров** | `1` | Бот не масштабируется горизонтально — state в одном файле |
| **Тип масштабирования** | `Concurrency` | Не имеет значения при max=1 |
| **Request-таймаут** | `600` | Стандартное значение |
| **Idle-таймаут** | `1800` | Не используется при min=1 |

> **Если min instances = 0:** контейнер уснёт через 30 минут без входящих HTTP-запросов, и бот перестанет получать сообщения VK.

#### Дополнительные опции

- **Публичный адрес:** `Выключен` — бот не предоставляет HTTP API
- **Авторизация:** не требуется без публичного адреса
- **Автоматическое развертывание:** `Включено` (при пуше нового образа в Artifact Registry)
- **Логирование запросов:** `Включено` (для отладки)

### Шаг 5: Запуск

Нажмите **Создать**. Контейнер запустится в течение 1–2 минут.

Проверьте статус: панель управления → Container Apps → ваш контейнер → должен быть в статусе **«Выполняется»**.

### Шаг 6: Проверка работы

1. Откройте логи контейнера в панели cloud.ru
2. Убедитесь, что бот стартовал без `ValidationError`
3. Напишите `?` в групповом чате VK — бот должен показать справку
4. После анонса проверьте `записаться`, перезапустите ревизию и убедитесь, что участник сохранился

## Способ 2: Container Apps без persistent volume (данные в S3 напрямую)

Если хотите избежать монтирования S3 как FS (может быть медленным для частых JSON-перезаписей), можно:

1. Не монтировать том в Container Apps
2. Изменить `src/storage.py` для работы с Object Storage напрямую через `boto3`
3. Или использовать SQLite + S3 sync

Это требует модификации кода и выходит за рамки данного руководства. Для MVP с ≤100 участников persistent volume (S3) работает достаточно быстро.

## Обновление бота

При включённом **автоматическом развёртывании**:

```bash
# Локально: внесите изменения, коммит, пуш в основную ветку репозитория
git push origin main

# Сборка и пуш нового образа
IMAGE_URI=<полный-URI-образа-из-Artifact-Registry>
docker build -t "$IMAGE_URI" .
docker push "$IMAGE_URI"
```

Container Apps автоматически создаст новую **ревизию** и перезапустит контейнер.

> Данные в постоянном томе сохраняются между ревизиями. Проверяйте это
> контрольной записью после изменений конфигурации тома.

## Мониторинг

### Логи

Панель управления → Container Apps → ваш контейнер → **Логи**.

### Метрики

- **Использование vCPU / RAM** — чтобы подобрать оптимальную конфигурацию
- **Количество запросов** — для VK бота обычно 0 (нет входящего HTTP)
- **Статус ревизии** — «Выполняется» = бот работает

### Оповещения (опционально)

Настройте алерты в cloud.ru Monitoring на статус контейнера. Если ревизия перейдёт в статус **«Ошибка»** или **«Остановлена»**, вы получите уведомление.

## Типичные проблемы

### Контейнер перезапускается циклически

Причины:
- `VK_TOKEN` не задан или невалидный — бот падает при старте
- Health-проба падает — проверьте команду и начальную задержку
- Процесс не запускается — убедитесь, что `CMD` в Dockerfile не перезаписан неверной командой или аргументами

### Данные не сохраняются между ревизиями

- Проверьте, что **постоянный том** смонтирован на `/app/data`
- Проверьте, что `DATA_PATH=/app/data/participants.json` и том смонтирован на `/app/data`
- Убедитесь, что бакет Object Storage создан в **том же проекте**, что и Container Apps

### Бот не отвечает в чате через 30+ минут

- Проверьте **минимальное количество экземпляров** — должно быть `1`, не `0`
- Проверьте логи: если контейнер ушёл в статус **«Завершён»**, значит min instances = 0 и сработал idle-таймаут

### Scheduler не срабатывает

- `TZ=Europe/Moscow` должен быть установлен как переменная окружения в Container Apps
- Проверьте `COLLECT_*` для анонса и `EVENT_*` для начала тренировки

### Нет доступа к VK API

```bash
# Внутри контейнера (через SSH/консоль в панели, если доступна)
curl -I https://api.vk.com
```

Если нет ответа — проверьте настройки сети в проекте cloud.ru. Обычно исходящий интернет доступен по умолчанию.

## Стоимость

Постоянный «горячий» экземпляр тарифицируется даже без входящих запросов.
Стоимость также зависит от Object Storage, Artifact Registry и трафика;
проверьте текущие условия в [прайсе cloud.ru](https://cloud.ru/pricing).

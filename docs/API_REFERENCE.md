# Справочник API

Документ описывает текущие публичные и значимые внутренние контракты модулей
`src/`. Пользовательский сценарий приведён в `BOT_COMMANDS.md`.

## `src/config.py`

### `Config(BaseSettings)`

Загружает `.env`, валидирует токен, `CHAT_PEER_ID`, расписание, путь к JSON и
список администраторов. Время задаётся строкой `HH:MM`, день недели — числом
`0..6`, где `0` означает понедельник.

Основные вычисляемые свойства: `collect_hour`, `collect_minute`, `event_hour`,
`event_minute`, `remind_hour`, `remind_minute`, `path`. Метод
`is_admin(vk_id)` проверяет членство в `ADMIN_VK_IDS_RAW`.

## `src/storage.py`

### Модели

- `UserEntry`: участник VK с `vk_id` и именем.
- `FriendEntry`: добавленный по имени друг.
- `Entry`: discriminated union этих моделей по полю `kind`.
- `RegistrationSnapshot`: неизменяемый согласованный снимок участников,
  жизненного цикла, дедлайна и обоих VK ID карточки.

### `Storage(path)`

JSON-хранилище с `asyncio.Lock`. Каждая запись сначала сохраняется во временный
файл и атомарно заменяет основной. Живое состояние меняется только после
успешного сохранения.

Основные методы:

| Метод | Назначение |
|---|---|
| `list_entries()` | Вернуть копию списка участников |
| `snapshot()` | Вернуть один согласованный снимок всех данных карточки |
| `add_user(...)`, `remove_user(...)` | Добавить или убрать участника VK |
| `add_friend(...)`, `remove_friend(...)` | Добавить или убрать друга |
| `remove_by_name(name)` | Удалить первую запись с указанным именем |
| `clear()` | Очистить участников, сохранив жизненный цикл события |
| `begin_event(start, source)` | Атомарно перейти `closed → opening` и сохранить дедлайн |
| `activate_event(message_id, expected_start, conversation_message_id=...)` | Проверить актуальность события, очистить прошлый список и перейти `opening → open` |
| `close_registration()` | Перейти `open/opening → closed`, сохранив итоговый список |
| `close_missing_deadline()` | Закрыть повреждённое активное состояние без дедлайна |
| `set_status_message_id(message_id, conversation_message_id=...)` | Сохранить адрес канонической карточки |

`expected_collection` в методах добавления защищает от задержавшегося запроса:
участник не попадёт в новый сбор, если за время запроса VK номер сбора изменился.

## `src/formatting.py`

- `format_entries(entries)` строит нумерованный список и помечает друзей.
- `format_event_start(value)` показывает русский день недели, дату и время.
- `format_registration_card(entries, state, event_starts_at, notice=None)`
  строит единственную карточку с состоянием, полной датой, временем закрытия и
  участниками. `notice` добавляет временное пояснение внутри карточки.
- `help_text(compact=False)` возвращает справку по пользовательским командам.

## `src/keyboard.py`

`build_inline_keyboard()` возвращает JSON inline-клавиатуры с payload:
`join`, `leave`, `list`, `help`.

## `src/cards.py`

### `MessageRef`

Хранит `message_id` и `conversation_message_id`. Свойство `usable` истинно,
если хотя бы один ID положительный.

### `CardPublisher(api, config, storage)`

Единая точка всех видимых обновлений. Внутренняя блокировка не позволяет
параллельным обработчикам опубликовать устаревший снимок после более нового.

| Метод | Контракт |
|---|---|
| `replace_current(notice=None)` | Отправить карточку через `peer_ids`, сохранить оба ID, затем удалить предыдущую |
| `edit_current(notice=None)` | Изменить карточку по `conversation_message_id` или `message_id`; при ошибке безопасно заменить |
| `publish_event(start, random_id, activate)` | Отправить пустую карточку и активировать событие только после получения рабочего ID |
| `diagnostic_notice()` | Вернуть состояние, начало, источник и оба ID для админа |

Если VK принял отправку, но не вернул рабочий ID, выбрасывается
`CardIdentityError`; старая карточка и ссылка на неё сохраняются. Если не удалось
сохранить новый ID, новая карточка удаляется, а предыдущая остаётся канонической.

## `src/bot.py`

### `setup_handlers(bot, storage, config, cards=None)`

Регистрирует текстовые, callback и административные обработчики. Все они
сначала проверяют `peer_id`.

Текстовые команды не вызывают `msg.answer`: после обработки
`CardPublisher.replace_current()` ставит актуальную карточку последним
сообщением. Успешная операция видна по списку; ошибка или справка передаются в
`notice` и исчезают при следующем обновлении.

Callback-кнопки используют `show_snackbar`. При изменении списка вызывается
`CardPublisher.edit_current()`; новые сообщения в чат не создаются.

Админ-команды:

- `создать событие ДД.ММ.ГГГГ ЧЧ:ММ`;
- `очистить` / `сбросить`;
- `убрать Имя` / `удалить Имя`;
- `статус события`;
- `админ помощь`.

## `src/scheduler.py`

- `_next_target(...)` вычисляет следующее наступление недельного времени.
- `_weekly_event_after(...)` вычисляет начало тренировки после анонса.
- `_pick_next_event(...)` выбирает ближайший анонс, reminder или дедлайн.
- `_run_with_retry(...)` повторяет сетевую операцию через пять минут, но не
  продолжает публикацию анонса после начала события.
- `open_manual_event(...)` проверяет будущее время, активное событие и
  пересечение со следующим недельным анонсом.
- `run_scheduler(...)` восстанавливает состояние, планирует анонсы,
  напоминания и закрытие.

Переход недельного или ручного события:

1. `begin_event()` сохраняет `event_starts_at`, источник и `random_id` в
   состоянии `opening`.
2. `CardPublisher.publish_event()` отправляет карточку с тем же `random_id`.
3. Callback активации повторно проверяет дедлайн и вызывает `activate_event()`
   с обоими VK ID.
4. В момент начала `close_registration()` фиксирует `closed`, после чего
   карточка редактируется. Ошибка VK не отменяет закрытое состояние на диске.

При запуске `open`/`opening` без `event_starts_at` закрывается через
`close_missing_deadline()`. Просроченное событие также закрывается до ожидания
следующего действия.

## `src/main.py`

`main()` настраивает журналирование, создаёт `Config`, `Storage`, `Bot` и общий
`CardPublisher`. Затем в одном `anyio.TaskGroup` запускает `run_scheduler()` и
`bot.run_polling()`.

## Исключения и восстановление

| Сбой | Поведение |
|---|---|
| Невалидный `.env` или JSON | Процесс завершается при старте с ошибкой в журнале |
| `users.get` вернул `VKAPIError` | Операция отклоняется, причина показывается в карточке/snackbar |
| Отправка карточки временно недоступна | Планировщик повторяет до дедлайна с сохранённым `random_id` |
| VK не вернул рабочий ID | Событие не активируется, старая карточка сохраняется |
| Редактирование карточки не удалось | Публикуется замена и сохраняются её ID |
| Сохранение JSON не удалось | Живое состояние и старая карточка остаются актуальными |
| Бот запущен после начала | Регистрация сразу фиксируется как закрытая |

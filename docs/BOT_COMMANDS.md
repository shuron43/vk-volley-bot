# Команды бота

Бот реагирует на текстовые сообщения и callback-события только в чате из
`CHAT_PEER_ID`. События из других peer полностью игнорируются.

## Краткая справка

| Команда | Описание | Требует имя? |
|---------|----------|--------------|
| `записаться` | Записать себя | Нет |
| `-` или `отписаться` | Убрать себя | Нет |
| `+` | Подсказка, как записаться (не добавляет вас) | Нет |
| `+ Имя` | Записать друга, пока запись открыта | Да |
| `- Имя` | Убрать друга | Да |
| `список` / `участники` / `кто идёт` | Показать участников | Нет |
| `?` / `help` / `помощь` / `команды` | Показать справку | Нет |

## Подробное описание

### Записаться

**Синтаксис:**
```
записаться
```

**Что происходит:**
1. Бот проверяет, что запись открыта
2. Определяет ваш vk_id из сообщения
3. Запрашивает ваше имя через VK API (users.get)
4. Добавляет вас в хранилище как UserEntry

**Ответы бота:**
- Ты записался! — при успешной записи
- Ты уже в списке. — если вы уже записаны
- Запись ещё не открыта. Дождись анонса сбора или нажми «Помощь». — если сбор ещё не анонсирован

**Особенности:**
- Имя берётся из VK (first_name). Если VK API вернёт пустой ответ или first_name отсутствует — будет Unknown. Ошибка VK API перехватывается, а пользователь получает предложение повторить позже.
- Повторная запись невозможна (проверка по vk_id).
- Запись возможна только пока регистрация открыта (состояние `open`). До анонса сбора и во время подготовки анонса (состояние `opening`) команда отклоняется с тем же сообщением. См. [раздел о жизненном цикле](#жизненный-цикл-регистрации) ниже.

### Подсказка по записи (+)

**Синтаксис:**
```
+
+
(с пробелами)
```

**Что происходит:**
- Бот не добавляет вас в список. Вместо этого отправляет подсказку, как правильно записаться.
- Хендлер `bare_plus` зарегистрирован отдельно от `записаться`, поэтому `+` (включая `+   ` с одними пробелами) никогда не вызывает ни VK API, ни запись в хранилище.

**Ответ бота:**
```
Чтобы записаться, нажми «Записаться» или напиши «записаться» после анонса. Для друга: + Имя.
```

**Особенности:**
- `+` без имени никогда не мутирует список участников — ни до открытия записи, ни после.
- Полезна для новичков, которые не знают, что запись открывается только после анонса, и для тех, кто по привычке отправляет `+` как быструю команду.
- Для явной самозаписи используйте `записаться` или кнопку **✅ Записаться**.

### Отписаться (-)

**Синтаксис:**
```
-
отписаться
```

**Что происходит:**
1. Бот ищет ваш vk_id в хранилище
2. Удаляет запись, если найдена

**Ответы бота:**
- Ты отписался. — при успехе
- Тебя не было в списке. — если вы не были записаны

### Записать друга (+ Имя)

**Синтаксис:**
```
+ Андрей
+  Мария  (лишние пробелы обрезаются)
```

**Что происходит:**
1. Бот извлекает текст после символа +
2. Убирает ведущие и конечные пробелы
3. Проверяет состояние регистрации (`is_registration_open()`)
4. Добавляет запись типа FriendEntry (без vk_id)

**Ответы бота:**
- `{имя} записан(а) как друг.` — при успехе
- `Укажи имя друга: + Имя` — если после `+` пусто (перехватывается до проверки регистрации)
- `Запись ещё не открыта. Дождись анонса сбора или нажми «Помощь».` — если запись друга отправлена, пока регистрация закрыта или в состоянии `opening`

**Особенности:**
- Дубликаты допускаются — можно записать двух друзей с одинаковым именем.
- Регистр сохраняется как есть.
- Имя должно быть непустым и не длиннее 100 символов.
- Запись друга через inline-кнопку невозможна — требует ввода имени. Используйте текстовую команду `+ Имя`.

### Убрать друга (- Имя)

**Синтаксис:**
```
- Андрей
```

**Что происходит:**
1. Бот извлекает текст после -
2. Ищет первое точное совпадение по имени среди FriendEntry
3. Удаляет найденную запись

**Ответы бота:**
- {имя} убран(а) из списка. — при успехе
- Такого друга не нашлось. — если имя не найдено

**Особенности:**
- Удаляется только первое совпадение. Если два друга с одинаковым именем — нужно вызвать команду дважды.
- Сравнение точное (case-sensitive). `- андрей` и `- Андрей` — разные строки.

### Список участников

**Синтаксис:**
```
список
участники
кто идёт
```

**Что происходит:**
1. Бот читает текущий список из хранилища
2. Формирует нумерованный список

**Формат ответа:**
```
Список участников:
1. Алексей
2. Мария
3. Андрей (друг)
```

**Ответ если пусто:**
- Пока никто не записался.

### Помощь

**Синтаксис:**
```
?
help
помощь
команды
```

**Ответ бота:**
```
Запись открывается после анонса сбора.
Для себя — «записаться» или кнопка «✅ Записаться».
Чтобы отписаться — «отписаться» или кнопка «↩️ Отписаться».
`+` без имени подскажет, как записаться, но не добавит вас.
+ Имя — записать друга, пока запись открыта.
- Имя — убрать друга.
📋 список — кто идёт.
❓ ? — помощь
```

> Текст справки общий для команды `?` и кнопки **❓ Помощь**. Один источник — `help_text()` в `src/formatting.py`.

## Примеры диалога

### Сценарий 1: запись и просмотр списка (после анонса)

```
Алексей: записаться
Бот: Ты записался!

Мария: записаться
Бот: Ты записался!

Дмитрий: список
Бот:
Список участников:
1. Алексей
2. Мария
```

### Сценарий 2: запись друга (пока регистрация открыта)

```
Алексей: + Андрей
Бот: Андрей записан(а) как друг.

Мария: список
Бот:
Список участников:
1. Алексей
2. Андрей (друг)
```

### Сценарий 3: отписка

```
Алексей: -
Бот: Ты отписался.

Мария: список
Бот:
Список участников:
1. Андрей (друг)
```

### Сценарий 4: попытка повторной записи

```
Алексей: записаться
Бот: Ты записался!

Алексей: записаться
Бот: Ты уже в списке.
```

### Сценарий 5: `+` без имени (подсказка, не запись)

```
Алексей: +
Бот: Чтобы записаться, нажми «Записаться» или напиши «записаться» после анонса. Для друга: + Имя.

Мария: список
Бот:
Список участников:
1. Алексей
```

> `+` не изменил список — Алексей уже был записан через `записаться` ранее.

### Сценарий 6: попытка записи до открытия регистрации

```
Алексей: записаться
Бот: Запись ещё не открыта. Дождись анонса сбора или нажми «Помощь».

Алексей: + Андрей
Бот: Запись ещё не открыта. Дождись анонса сбора или нажми «Помощь».

Алексей: -
Бот: Тебя не было в списке.
```

> До анонса сбора закрыты только добавления (`записаться`, `+ Имя`). Удаление, `список` и `?` работают в любом состоянии.

## Inline-клавиатура

Каждый ответ бота сопровождается inline-клавиатурой:

```
✅ Записаться   ↩️ Отписаться
📋 Список      ❓ Помощь
```

### Кнопки

| Кнопка | Действие | Эквивалент |
|--------|----------|------------|
| ✅ Записаться | Записать себя | `записаться` |
| ↩️ Отписаться | Отписаться | `-` |
| 📋 Список | Показать участников | `список` |
| ❓ Помощь | Показать справку | `?` |

### Как работают callback-кнопки

1. Пользователь нажимает кнопку в VK
2. VK отправляет событие `message_event` боту (без текстового сообщения в чат)
3. Бот обрабатывает событие и:
   - **✅ Записаться** / **↩️ Отписаться** — сначала выполняет действие, затем показывает snackbar (`show_snackbar`) с ответом и, если список изменился, обновляет каноническое статусное сообщение бота через `messages.edit` (новое сообщение не отправляется)
   - **📋 Список** / **❓ Помощь** — пытается отредактировать то сообщение, к которому привязана нажатая кнопка (`event.edit_message`); при успехе показывает короткий snackbar-подтверждение
4. Если VK отклонил редактирование (`VKAPIError`), бот **ровно один раз** отправляет замену через `messages.send` с криптографически случайным `random_id` и сохраняет её ID как новый канонический статус (`set_status_message_id`)
5. Другие участники чата **не видят** нажатие кнопки и **не получают** нового сообщения при успешном редактировании

> **Ограничение:** Запись друга (`+ Имя`) через inline-кнопку невозможна, так как требует ввода имени. Используйте текстовую команду.

> **Тихое поведение:** при удачном редактировании чат видит только snackbar у нажавшего; новых сообщений от бота в общий чат не уходит — обновляется уже существующее сообщение бота.

## Жизненный цикл регистрации

Регистрация живёт в одном из трёх состояний, которые хранятся в JSON вместе с
участниками и `status_message_id`:

| Состояние | Что означает | Какие команды работают |
|-----------|--------------|------------------------|
| `closed` | Нового сбора ещё не было или он завершён | `список`, `?`, `-`, `- Имя`, админ-команды |
| `opening` | Бот готовится отправить анонс; состояние сохраняется до успешной отправки | Те же, что и в `closed` |
| `open` | Анонс ушёл, запись открыта | Все команды, включая `записаться` и `+ Имя` |

Состояние проверяется через `Storage.is_registration_open()` в хелперах
`join_user` и `add_friend_by_name` — это общие помощники для текстовых команд и
callback-кнопок. Попытка записаться, пока состояние отлично от `open`, даёт
ответ:

```
Запись ещё не открыта. Дождись анонса сбора или нажми «Помощь».
```

> **Восстановление после сбоя:** если бот перезапустился в состоянии `opening` (анонс не успел уйти), `_load()` нормализует его обратно в `closed`, **сохраняя** участников. Очистка выполняется только в составе `start_new_collection()` уже после успешной отправки.

## Автоматический анонс

Раз в неделю (в заданный день и время) бот автоматически запускает новый сбор:

1. **Перед отправкой** — бот переводит регистрацию в состояние `opening`, сохраняя текущих участников. Это защищает список от случайной записи во время подготовки анонса.
2. **Отправка** — бот публикует сообщение с inline-клавиатурой:

```
🏐 Сбор на волейбол!
Кто идёт? Напиши «записаться» или имя друга через +
список — посмотреть участников
```

3. **После успешной отправки** — бот атомарно очищает список участников и открывает запись (`open`).

Если отправка в VK временно не удалась, повторяется только отправка через пять
минут; старый список участников сохраняется до тех пор, пока анонс не будет
доставлен успешно. После перезапуска бота состояние `opening` безопасно
нормализуется обратно в `closed`.

## Автоматическое напоминание

В заданный день и время (независимо от дня сбора) бот автоматически отправляет напоминание:

```
🏐 Напоминаем: сбор на волейбол!

Список участников:
1. Алексей
2. Мария
3. Андрей (друг)
```

Напоминание **не очищает** список — оно только показывает текущее состояние записи. Настраивается через `REMIND_ENABLED`, `REMIND_WEEKDAY` и `REMIND_TIME`.

## Админ-команды

Доступны только пользователям, чьи положительные VK ID указаны в
`ADMIN_VK_IDS_RAW`. Строка разбирается при старте; пустые элементы и нечисловые
значения не допускаются.

### Очистить список

**Синтаксис:** `очистить` или `сбросить`

**Что происходит:**
1. Бот проверяет, что отправитель — администратор
2. Очищает весь список участников
3. Отправляет подтверждение

**Ответ бота:** `Список участников очищен.`

### Удалить участника

**Синтаксис:** `убрать Имя` или `удалить Имя`

**Что происходит:**
1. Бот проверяет, что отправитель — администратор
2. Ищет первого участника с точным совпадением по имени (VK-пользователя или друга)
3. Удаляет найденную запись

**Ответы бота:**
- `{имя} убран(а) из списка.` — при успехе
- `Такого участника не нашлось.` — если имя не найдено

### Админ-справка

**Синтаксис:** `админ помощь` или `admin help`

**Ответ бота:**
```
Админ-команды:
очистить / сбросить — очистить список участников
убрать Имя / удалить Имя — удалить участника по имени
админ помощь — показать эту справку
```

## Ограничения MVP

- Лимит списка фиксирован: 100 участников; очереди ожидания нет
- Нет статистики по посещаемости

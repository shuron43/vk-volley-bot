# Команды и сценарий работы бота

Бот работает только в беседе из `CHAT_PEER_ID`. В чате поддерживается одна
актуальная карточка события с датой, временем, состоянием и участниками.

## Карточка события

Открытая запись выглядит так:

```text
🏐 Волейбол — запись открыта
📅 Вторник, 22 сентября 2026
🕢 Начало: 19:30
⏳ Запись закроется автоматически в 19:30

Участники: 2
1. Александр
2. Петя (друг)
```

После начала первая строка меняется на `🏐 Волейбол — запись закрыта`, строка
про будущее закрытие исчезает, итоговый список сохраняется.

После любой обработанной текстовой команды бот отправляет свежую карточку
последним сообщением и удаляет предыдущую. Отдельных ответов бота нет. Ошибка
или справка временно появляется внизу карточки и исчезает после следующего
действия.

## Пользовательские команды

| Команда | Действие |
|---|---|
| `записаться` | Записать автора сообщения, если регистрация открыта |
| `-`, `отписаться` | Убрать автора из списка |
| `+` | Показать подсказку; команда не записывает автора |
| `+ Имя` | Записать друга, пока регистрация открыта |
| `- Имя` | Убрать друга |
| `список`, `участники`, `кто идёт` | Переместить актуальную карточку в конец чата |
| `?`, `help`, `помощь`, `команды` | Показать полную справку внутри карточки |

## Кнопки

Под карточкой находятся:

```text
✅ Записаться   ↩️ Отписаться
📋 Список      ❓ Помощь
```

- **Записаться** и **Отписаться** меняют список, редактируют карточку на месте
  и показывают результат через snackbar.
- **Список** обновляет карточку на месте и подтверждает действие snackbar.
- **Помощь** показывает короткую подсказку snackbar.

Нажатия не создают сообщений. VK разрешает snackbar только для callback-кнопок:
у обычного текстового сообщения нет необходимого `event_id`.

## Жизненный цикл регистрации

### Еженедельное событие

`COLLECT_WEEKDAY` и `COLLECT_TIME` задают момент анонса. `EVENT_WEEKDAY` и
`EVENT_TIME` задают начало тренировки. При стандартной настройке анонс выходит
в понедельник в 08:00, тренировка начинается во вторник в 19:30.

Порядок открытия:

1. Бот сохраняет начало события и состояние `opening`.
2. Публикует карточку и получает рабочий `message_id` или
   `conversation_message_id`.
3. Очищает список прошлого сбора и переводит регистрацию в `open`.
4. В момент начала сначала сохраняет `closed` на диске, затем обновляет
   карточку. Итоговый список не очищается.

Если VK временно недоступен, публикация повторяется через пять минут, но не
после начала события. После перезапуска сохранённое событие продолжает ждать
своего дедлайна; просроченное закрывается сразу. Повреждённое активное состояние
без дедлайна также закрывается при запуске.

### Ручное событие

Администратор отправляет:

```text
создать событие 22.09.2026 19:30
```

Карточка и запись открываются сразу, закрытие происходит в указанное время.
Команда отклоняется, если время прошло, уже есть активное событие или ручное
событие достигнет следующего еженедельного анонса.

## Админ-команды

Доступ определяет `ADMIN_VK_IDS_RAW`.

| Команда | Действие |
|---|---|
| `создать событие ДД.ММ.ГГГГ ЧЧ:ММ` | Открыть ручное событие |
| `очистить`, `сбросить` | Очистить список текущего события |
| `убрать Имя`, `удалить Имя` | Удалить участника по имени |
| `статус события` | Показать состояние, начало, источник и оба VK ID в карточке |
| `админ помощь`, `admin help` | Показать админ-справку в карточке |

Попытка не администратора не меняет данные; причина показывается внутри
карточки.

## Ограничения

- не более 100 участников;
- имя не длиннее 100 символов;
- ввод имени друга остаётся текстовой командой;
- обычные сообщения, которые не являются командами, не перемещают карточку;
- несколько процессов с одним JSON запускать нельзя.

# Команды и сценарий работы бота

Бот работает только в беседе из `CHAT_PEER_ID`. В чате поддерживается одна
актуальная карточка события с датой, временем, состоянием и участниками.

## Карточка события

Открытая запись выглядит так:

```text
🏐 Волейбол — запись открыта
📅 Вторник, 22 сентября 2026
🕢 Начало: 19:30
⏳ Запись закроется автоматически в 19:30

Участники: 2
1. Александр
2. Петя (друг)
```

После начала первая строка меняется на `🏐 Волейбол — запись закрыта`, строка
про будущее закрытие исчезает, итоговый список сохраняется.

В первые 30 минут после начала участник ещё может отписаться: его имя
сохраняется с `(-)` и переносится в низ списка. Повторная запись в этот период
снимает минус и возвращает имя выше отписавшихся. Новые участники после начала
не добавляются. Ровно через 30 минут отписка и возврат блокируются.
Правило одинаково для кнопок, текстовых команд и друзей (`- Имя` / `+ Имя`).
Счётчик «Участники» включает только тех, кто не отписался. Например:

```text
Участники: 2
1. Александр
2. Петя (друг)
3. Иван (-)
```

До начала отписка удаляет строку целиком. Возврат после начала доступен
только участникам с сохранённой отметкой `(-)` текущего события.

После любой обработанной текстовой команды бот отправляет свежую карточку
последним сообщением и удаляет предыдущую. Отдельных ответов бота нет. Ошибка
или справка временно появляется внизу карточки и исчезает после следующего
действия.

## Пользовательские команды

Все текстовые команды принимают заглавные буквы и пробелы по краям:
`Записаться`, `  СПИСОК  ` и `Помощь` работают. В `+ Имя` / `- Имя`
пробелы по краям команды убираются, регистр самого имени сохраняется.

| Команда | Действие |
|---|---|
| `записаться` | Записаться до начала или снять свой `(-)` в первые 30 минут |
| `-`, `отписаться` | Отписаться; после начала оставить имя с `(-)` в первые 30 минут |
| `+` | Показать подсказку; команда не записывает автора |
| `+ Имя` | Записать друга до начала или снять его `(-)` в первые 30 минут |
| `- Имя` | Отписать друга по тому же правилу |
| `список`, `участники`, `кто идёт` | Переместить актуальную карточку в конец чата |
| `?`, `help`, `помощь`, `команды` | Показать полную справку внутри карточки |

## Кнопки

Под карточкой находятся:

```text
✅ Записаться   ↩️ Отписаться
❓ Помощь
```

- **Записаться** и **Отписаться** меняют список, редактируют карточку на месте
  и показывают результат через snackbar.
- **Помощь** показывает короткую подсказку snackbar, включая команду
  `список — показать актуальную карточку в конце чата`.

Нажатия не создают сообщений. VK разрешает snackbar только для callback-кнопок:
у обычного текстового сообщения нет необходимого `event_id`.

## Жизненный цикл регистрации

### Еженедельное событие

`COLLECT_WEEKDAY` и `COLLECT_TIME` задают момент анонса. `EVENT_WEEKDAY` и
`EVENT_TIME` задают начало тренировки. При стандартной настройке анонс выходит
в понедельник в 08:00, тренировка начинается во вторник в 19:30.

Порядок открытия:

1. Бот сохраняет начало события и состояние `opening`.
2. Публикует карточку и получает рабочий `message_id` или
   `conversation_message_id`.
3. Очищает список прошлого сбора и переводит регистрацию в `open`.
4. В момент начала сначала сохраняет `closed` на диске, затем обновляет
   карточку. Итоговый список не очищается.

Если VK временно недоступен, публикация повторяется через пять минут, но не
после начала события. После перезапуска сохранённое событие продолжает ждать
своего дедлайна; просроченное закрывается сразу. Повреждённое активное состояние
без дедлайна также закрывается при запуске.

### Ручное событие

Администратор отправляет:

```text
создать событие 22.09.2026 19:30
```

Карточка и запись открываются сразу, закрытие происходит в указанное время.
Команда отклоняется, если время прошло, уже есть активное событие или ручное
событие достигнет следующего еженедельного анонса.

## Админ-команды

Доступ определяет `ADMIN_VK_IDS_RAW`.

Админ-команды распознаются независимо от регистра: `Создать событие`,
`СОЗДАТЬ СОБЫТИЕ` и `создать событие` равнозначны. Пробелы по краям и несколько
пробелов между словами команды допустимы; регистр имени участника сохраняется.
Время создаваемого события должно быть в будущем. При неверном формате,
прошедшем времени или отсутствии прав причина отправляется автору лично.

| Команда | Действие |
|---|---|
| `создать событие ДД.ММ.ГГГГ ЧЧ:ММ` | Открыть ручное событие |
| `удалить событие` | Отменить событие, очистить участников и удалить карточку |
| `очистить`, `сбросить` | Очистить список текущего события |
| `убрать Имя`, `удалить Имя` | Удалить участника по имени |
| `статус события` | Показать состояние, начало, источник и оба VK ID в личном сообщении |
| `админ помощь`, `admin help` | Отправить админ-справку лично |

Все распознанные админ-команды удаляются для всех до выполнения действия,
включая ошибки и отказы в доступе. Для удаления сообщений участников сообществу
нужны права администратора беседы. Отказ VK удалять команду не отменяет действие;
автор получает личное предупреждение. Попытка не администратора не меняет данные.

Справка, статус и ошибки не попадают в карточку. Для получения личных ответов
открой диалог с сообществом, напиши ему и разреши сообщения. Если доставка
запрещена, бот логирует ошибку без публикации справки в беседе.

Удаление события очищает участников, время начала и источник события, закрывает
запись и убирает карточку. Работает также для закрытого события и незавершённого
анонса; отложенная повторная отправка отменённого анонса не создаст карточку.
При ошибке VK событие отменяется, но ID карточки сохраняются: после восстановления
доступа повтори `удалить событие`. Еженедельное расписание не отключается.

## Ограничения

- не более 100 участников;
- имя не длиннее 100 символов;
- ввод имени друга остаётся текстовой командой;
- обычные сообщения, которые не являются командами, не перемещают карточку;
- несколько процессов с одним JSON запускать нельзя.
